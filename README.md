# 禁漫号查询插件（local.jm-lookup）

在群里检测到「禁漫天堂本子号」时，自动抓取该本子的**标题+作者**并回帖；可选附带**封面图**（本地 AI 自动打码）。支持引用原消息、打包成聊天记录、注入上下文、分群开关、漏检兜底。

> 面向 MaiBot（maibot-plugin-sdk）。只依赖 jmcomic（抓数据）+ 一个本地打码服务（onnx，可选，用于发封面）。

---

## 一、整体情况

### 它做什么
群里有人发 `JM123456` / `禁漫123456` / `本子123456`（或纯数字，可配）时：
1. 识别出本子号
2. 用 `jmcomic` 库抓取**标题**和**作者**
3. 回帖：`《标题》 作者：xxx`
4. （可选）下载封面 → 送给本地打码服务做**马赛克/模糊** → 一起发出
5. （可选）引用发出者那条原消息 / 打包成一条合并转发（聊天记录）/ 把结果注入麦麦上下文
6. （可选）漏检兜底：判定为敏感但一个部位都没检出时，整图打码或干脆不发封面，防漏

### 架构
```
QQ群消息 ──► MaiBot 插件(jm_lookup) ──► jmcomic库 ──► 标题/作者
                     │
                     └─(发封面时)──► 本地打码服务(onnx_api, 127.0.0.1:8000)
                                        ├─ 分类判敏感(hentai/porn/sexy)
                                        ├─ 动漫分割模型检出敏感部位 → 马赛克/模糊
                                        └─ 兜底(检出过少→整图打码/不发)
```

### 依赖
- Python 运行时（MaiBot venv）：`jmcomic`、`httpx`（通常已随 MaiBot/openai 库存在）
- 打码服务（独立进程，onnxruntime，无需 torch）：见第五节
- 打码服务是**可选**的：不开封面 / 服务挂了，插件只发标题，不会报错

---

## 二、安装

1. 把本目录放到 `MaiBot/plugins/jm_lookup/`（目录名随意，manifest 里的 id 是 `local.jm-lookup`）。
2. 在 MaiBot venv 装抓取库：
   ```bash
   python -m pip install jmcomic httpx
   ```
3. 重启 MaiBot（`systemctl restart maibot`），在 WebUI「插件」页能看到「禁漫号查询」。
4. 需要发封面的话，按第五节部署本地打码服务（默认地址 `http://127.0.0.1:8000/process/`）。

## 三、命令

| 命令 | 作用 |
|---|---|
| `/jm 123456`（或 `/查本子 123456`、`/禁漫 123456`）| 手动查询某个本子号，直接返回标题+作者（走和自动触发相同的逻辑，也受分群开关限制）|

群消息里直接发本子号则**自动触发**（按「触发模式」判断）。

## 四、配置项详解（WebUI「插件 → 禁漫号查询」里逐项可调，或改 config.toml）

### A. 触发相关
| 配置 | 可选值 / 默认 | 作用 |
|---|---|---|
| **启用查询** | 开 / 关 | 插件总开关。关掉后不自动查、`/jm` 也不可用。 |
| **启用群（留空=全部）** | 群号/会话ID 列表，默认空 | **分群开关**。留空=所有群生效；填了群号（如 `123456789`）或会话ID，则只在这些群里触发。 |
| **触发模式** | `prefix`(默认) / `any` | `prefix`：必须「前缀+数字」才触发（只扫当前消息正文，不含引用的旧消息，最稳）；`any`：消息里出现纯数字（达到位数）就触发。 |
| **触发前缀** | 列表，默认 `JM/JMjm/禁漫/本子` | 仅 `prefix` 模式生效，大小写不敏感。例如发 `JM123`、`禁漫123`、`本子123` 都能命中。 |
| **最少位数** | 默认 4 | 仅 `any`（纯数字）模式用于过滤过短数字。 |
| **最多位数** | 默认 8 | 超过该位数的数字不当作本子号。 |
| **冷却(秒)** | 默认 60 | 同一个群这么多秒内只抓一次，防刷屏。填 0 = 不冷却（测试用）。 |
| **超时(秒)** | 默认 20 | 单次「抓标题/抓封面/打码」的网络超时。 |

### B. 回复内容
| 配置 | 可选值 / 默认 | 作用 |
|---|---|---|
| **显示作者** | 开(默认)/关 | 回复里是否带「作者：xxx」。关掉只回《标题》。 |
| **回复模板** | 默认 `《{title}》 作者：{author}` | 命中时的文案。变量：`{title}` 标题、`{author}` 作者。 |
| **无结果处理** | `silent`(默认) / `reply` | 没搜到时：`silent` 不回复；`reply` 回一句。 |
| **无结果文案** | 默认「没搜到这个本子」 | 仅 `无结果处理=reply` 时使用。 |

### C. 发送方式
| 配置 | 可选值 / 默认 | 作用 |
|---|---|---|
| **发送封面** | 开 / 关(默认) | 是否附带封面图。开启后封面会先送打码服务处理。**只有开启它，下面「打包/引用/打码」才有意义。** |
| **打包成聊天记录（关=分开发）** | 开(默认)/关 | **开**：标题+封面合成一条**合并转发（聊天记录）**，整洁；**关**：标题与封面分两条发（标题可引用原消息）。⚠️合并转发不支持引用原消息。 |
| **引用原消息** | 开(默认)/关 | 分开发模式下，回复**引用触发者那条消息**（QQ 引用气泡）。打包成聊天记录时自动忽略。 |
| **注入上下文** | 开(默认)/关 | 把结果写入 Maisaka 聊天上下文，这样麦麦后续被追问「刚那个本子叫啥」也能接上话。 |

### D. 打码（封面审查）
| 配置 | 可选值 / 默认 | 作用 |
|---|---|---|
| **打码样式** | `mosaic`(默认) / `blur` | 打码外观：`mosaic`=像素马赛克；`blur`=高斯模糊。 |
| **启用打码服务** | 开(默认)/关 | 让用户自己选择是否使用打码：开=封面送 API 打码后发出（需先部署打码服务）；关=不使用打码、不发封面（只发标题）。 |
| **打码 API 地址** | 默认 `http://127.0.0.1:8000/process/` | 本地打码服务的接口地址。 |
| **启用漏检兜底** | 开(默认)/关 | **兜底总开关**。开：判定敏感但一个部位都没检出时，按「兜底方式」处理；关：不兜底（可能漏）。 |
| **兜底方式** | `mosaic`(默认) / `blur` / `skip` | 触发兜底时怎么做：`mosaic`=整图马赛克；`blur`=整图模糊；`skip`=不发封面（只发标题）。 |
| **兜底覆盖阈值** | 默认 0 | `0`=关闭（推荐，只用「0框」判定兜底，避免正常小露点被误整图糊）；设 >0 则「检出覆盖率低于它」也触发兜底。 |
| **兜底最少框数** | 默认 1 | 检出框数少于它视为「过少」→ 触发兜底。默认 1 = 一个部位都没检出才兜底。 |

> 兜底逻辑：`判定敏感(hentai/porn/sexy)` 且 `(检出框数 < 最少框数)` 或（`覆盖率阈值>0` 且 `覆盖率<阈值`）→ 按兜底方式处理。这是「模型没检出、可能漏」时的安全网。

## 五、本地打码服务（onnx_api，可选）

一个基于 **onnxruntime** 的轻量服务（**不需要 torch**），跑二次元 NSFW 分割模型（来自 AutoHajimiMosaic / Forenche 的 `segmentation_model.onnx`）+ 分类模型。

### 接口
`POST /process/`（multipart 上传图，返回打码后的 jpg/png）
- 参数：`file`(图)、`output_format`(jpg/png)、`style`(mosaic/blur)、`block`(马赛克块，默认18)、`expand`(外扩像素，默认8)、`conf`(检测阈值，默认0.1)、`mask_classes`(要打的类别，空=全部)、`fallback`(mosaic/blur/skip/off)、`fallback_cover_ratio`(默认0)、`min_boxes`(默认1)
- 返回头：`X-Category`(分类)、`X-Cover`(覆盖率)、`X-Fallback`(是否兜底)、`X-Skip`(1=不发)

### 部署（systemd 常驻）
```bash
# 打码服务目录（含 onnx_api.py + models/*.onnx）
cd /path/to/AutoHajimiMosaic
# 依赖（无 torch）：
.venv/bin/pip install onnxruntime opencv-python-headless "fastapi" "uvicorn[standard]" python-multipart numpy
# systemd: /etc/systemd/system/autohajimi.service
#   WorkingDirectory=/path/to/AutoHajimiMosaic
#   ExecStart=.../uvicorn onnx_api:app --host 127.0.0.1 --port 8000
systemctl enable --now autohajimi
```

### 实测性能（16核/无GPU，本机）
- 单张处理 **~0.24 秒**（分类+分割+打码），常驻内存 **~338 MB**（清理后）
- 精简 venv 约 **729 MB**（去掉了 torch/nvidia/ultralytics）

---

## 六、2 核 4G 部署能跑吗？

**能，但有一个硬前提**：QQ 必须用**轻量协议端**（NapCat / Lagrange 等，约 200–400M），**不能用完整 QQ 客户端**（/opt/QQ GUI 版约 1.8G，直接爆）。

各组件实测内存参考：
| 组件 | 内存 |
|---|---|
| MaiBot（主进程+runner）| ~950 MB |
| SnowLuma | ~320 MB |
| 打码服务(onnx) | ~338 MB |
| 轻量 QQ 协议端 | ~300–500 MB |
| 系统/其他 | ~300–500 MB |
| **合计** | **约 2.4–2.6 G / 4 G** ✅ |

- CPU（2 核）：打码线程自适应（2 核→1 线程），单张 ~0.5s，群里偶尔查一次无压力。
- 磁盘：本插件很小；打码服务目录约 **0.8 G**；注意 MaiBot 的 a-memorix 数据目录可能较大。
- 想更省内存可：分类模型 int8 量化、打码服务改「按需启动」、提高冷却、不上封面（省 338M）。

## 七、测试方法
1. 群里直接发 `JM123456` / `禁漫123456` / `本子98765`（prefix 模式）→ 自动回标题+作者。
2. 发 `/jm 123456` → 手动查询。
3. 若开了「发送封面」：确认收到「聊天记录/封面」（应为正常马赛克，不是整图糊）。
4. 引用一条**旧的**带 jm 号的消息、只回一句「@某人 ？」→ 应**不再**误触发（只扫当前正文）。
5. 分群开关：把群号填进「启用群」后，未列出的群里发号应无反应。
6. 改「触发模式=any」→ 纯数字（够位数）也触发。

## 八、已知限制
- **兽人 / 非标准画风下体**：分割模型对"动漫人体"训练充分，对兽人/furry 的下体识别弱，可能漏（靠「漏检兜底」兜底整图/不发）。
- 抓取依赖禁漫镜像，jmcomic 会自动换域名；网络差时首次略慢。
- 封面打码服务是本地独立进程，需自行常驻；挂了只会退回「只发标题」。
